# Starstruck

## The rule

Create a repository that receives stars.

## Tiers

| Default | Bronze | Silver | Gold |
| --- | --- | --- | --- |
| 16 | 128 | 512 | 4096 |

The number is the star count on a single repository you created. Stars are added up per repository, not across all your repositories.

## Difficulty

Hard. It depends on other people finding your work useful.

## Steps

1. Pick a real problem: a tool you wished existed, a template, a cheat sheet or a learning resource.
2. Write a README that explains the project fast: what it is, why it exists, how to run it, and a screenshot if it has a screen.
3. Fill in the repository description and topics, and add a license, so people can find it and know they can use it.
4. Share it where the audience already is. Follow each community's rules about self-promotion.
5. Keep it alive. Answer issues, fix bugs and publish updates.

This repository is a practice run. It is small, specific and explains itself, which is the recipe.

## Common mistakes

- No README, so visitors cannot tell what the project does.
- Asking for stars in spam messages. It rarely works and annoys people.
- Counting stars from many different projects. The badge looks at one repository.

## Fair play

Do not buy stars or use bots to star repositories. GitHub's Acceptable Use Policies treat automated or purchased stars as rank abuse, and it damages your reputation with real users. Genuine stars are slow, but they mean something.
